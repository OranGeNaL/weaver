## Purpose

Домен описывает ИИ-ассистента HomeMusic: распознавание скриншотов, текстовых списков и ссылок, карточку подтверждения, создание загрузок и плейлистов, а также свободный чат с инструментами. Ассистент работает через внешний OpenAI-совместимый LLM и учитывает лимиты и стоимость каждого вызова.

## Requirements

### Requirement: Создание задачи ассистента

Hub SHALL принимать задачу из изображений, ссылки или текста и создавать `AssistantTask` со статусом `queued`. Для изображений MUST действовать ограничения по числу и размеру; для текста — ограничение длины сообщения.

#### Scenario: Задача со скриншотами
- **WHEN** пользователь отправляет изображения в `POST /api/assistant/tasks`
- **THEN** Hub сохраняет их во временный каталог задачи
- **AND** ставит задачу `assistant_task` в очередь

#### Scenario: Задача по ссылке
- **WHEN** пользователь отправляет поддерживаемую ссылку
- **THEN** Hub создаёт задачу с `input_kind: "link"`

#### Scenario: Задача по тексту
- **WHEN** пользователь отправляет текст
- **THEN** Hub создаёт задачу с `input_kind: "text"`

#### Scenario: Слишком много изображений
- **WHEN** число изображений превышает `MAX_IMAGES`
- **THEN** Hub возвращает `400`

#### Scenario: Слишком длинный текст
- **WHEN** текст последнего сообщения длиннее 5000 символов
- **THEN** Hub возвращает `400`

### Requirement: Распознавание скриншотов

Hub SHALL отправлять скриншоты vision-модели и MUST валидировать ответ модели. Строки без названия трека MUST отбрасываться; модель MUST NOT исполнять инструкции из изображения.

#### Scenario: Успешное распознавание
- **WHEN** модель вернула список строк
- **THEN** Hub очищает и валидирует строки через Pydantic
- **AND** сохраняет результат в `extraction_json`

#### Scenario: Модель вернула мусор
- **WHEN** ответ не соответствует ожидаемой структуре
- **THEN** задача завершается ошибкой без создания загрузок

#### Scenario: LLM не настроен
- **WHEN** `LLM_API_KEY` не задан и задача требует vision-модель
- **THEN** Hub возвращает ошибку о ненастроенном ИИ

### Requirement: Распознавание текста

Hub SHALL разбирать текстовый запрос через LLM, если LLM настроен, и MUST поддерживать быстрый путь без LLM для списков вида «Исполнитель - Название». Если запрос называет плейлист или исполнителя, Hub MUST вернуть соответствующий intent.

#### Scenario: Список без LLM
- **WHEN** LLM не настроен, а текст содержит строки «Artist - Title»
- **THEN** Hub извлекает треки без обращения к модели

#### Scenario: Текст с LLM
- **WHEN** LLM настроен
- **THEN** Hub получает intent, название плейлиста и список треков
- **AND** сохраняет стоимость и токены

#### Scenario: Запрос про исполнителя
- **WHEN** текст просит скачать или добавить исполнителя
- **THEN** Hub возвращает intent с артистом и не создаёт произвольный список треков

### Requirement: Извлечение треков из ссылок

Hub SHALL извлекать треки из ссылок Yandex Music, YouTube/YouTube Music и Spotify без LLM. Данные ссылки MUST считаться точными; неподдерживаемая ссылка MUST завершать задачу ошибкой.

#### Scenario: Ссылка Yandex Music
- **WHEN** пользователь отправляет ссылку на плейлист, альбом или трек Yandex Music
- **THEN** Hub получает точный список через Yandex Music API

#### Scenario: Ссылка YouTube
- **WHEN** пользователь отправляет ссылку YouTube или YouTube Music
- **THEN** Hub извлекает список через yt-dlp без скачивания аудио

#### Scenario: Ссылка Spotify
- **WHEN** пользователь отправляет публичную ссылку Spotify
- **THEN** Hub читает embed-страницу и извлекает доступные треки

#### Scenario: Неподдерживаемая ссылка
- **WHEN** ссылка не относится к поддерживаемым сервисам
- **THEN** задача завершается с `PermanentError`

### Requirement: Сопоставление и карточка подтверждения

Hub SHALL сопоставлять распознанные строки с библиотекой и каталогом и MUST показывать карточку подтверждения до побочных действий. Только подтверждение с `confirm_token` MUST создавать загрузки, плейлисты и другие изменения.

#### Scenario: Строка уже в библиотеке
- **WHEN** трек найден в библиотеке
- **THEN** строка помечается `owned`
- **AND** повторная загрузка не создаётся

#### Scenario: Строка найдена в каталоге
- **WHEN** трек сопоставлен с каталогом
- **THEN** строка получает `auto` при уверенном совпадении или `confirm` при слабом
- **AND** попадает в карточку подтверждения

#### Scenario: Строка не сопоставлена с каталогом
- **WHEN** трек не найден в каталоге, но найден файл hitmoz
- **THEN** строка получает `confirm` и варианты файлов

#### Scenario: Строка не найдена
- **WHEN** трек не удалось сопоставить
- **THEN** строка получает `not_found`
- **AND** пользователь может выбрать вариант вручную

#### Scenario: Подтверждение
- **WHEN** пользователь отправляет `confirm_token`
- **THEN** Hub создаёт batch загрузок и при необходимости плейлист
- **AND** связывает batch с задачей

#### Scenario: Без подтверждения
- **WHEN** задача находится в `awaiting_confirmation`
- **THEN** никакие загрузки и плейлисты ещё не созданы

#### Scenario: Неверный токен
- **WHEN** `confirm_token` не совпадает
- **THEN** Hub возвращает `403` и не выполняет действия

#### Scenario: Задача уже подтверждена или ещё не готова
- **WHEN** задача не находится в `awaiting_confirmation`
- **THEN** Hub возвращает `409`

### Requirement: Свободный чат с инструментами

Hub SHALL вести сохранённый чат с ассистентом, передавать модели историю и изображения и MUST выполнять только известные инструменты. Изменения, которые нельзя отменить, MUST выполняться только после подтверждения.

#### Scenario: Обычный вопрос
- **WHEN** пользователь отправляет сообщение без изменения данных
- **THEN** Hub возвращает ответ и стоимость
- **AND** сохраняет сообщения в чат

#### Scenario: Изменение через инструмент
- **WHEN** модель вызывает `create_playlist`, `star`, `enqueue_download` или другой разрешённый инструмент
- **THEN** Hub выполняет действие
- **AND** возвращает список `done` с описанием изменений

#### Scenario: Удаление плейлиста или файлов
- **WHEN** модель предлагает удалить плейлист или треки библиотеки
- **THEN** Hub создаёт proposal с `confirm_token`
- **AND** не выполняет удаление до подтверждения

#### Scenario: Отмена proposal
- **WHEN** пользователь вызывает dismiss
- **THEN** proposal становится `dismissed`
- **AND** токен больше не действует

#### Scenario: Чужой чат
- **WHEN** пользователь обращается к чату другого пользователя
- **THEN** Hub возвращает `404`

### Requirement: Лимиты и стоимость AI

Hub SHALL резервировать сообщение до начала работы ассистента и MUST вести учёт токенов и стоимости в `ai_usage`. Для неадминистраторов MUST действовать суточное ограничение сообщений.

#### Scenario: Первое сообщение дня
- **WHEN** пользователь впервые за день обращается к ассистенту
- **THEN** Hub создаёт запись `assistant_daily_usage` и резервирует сообщение

#### Scenario: Лимит исчерпан
- **WHEN** неадминистратор исчерпал суточный лимит
- **THEN** Hub возвращает `429` и не вызывает LLM

#### Scenario: Учёт стоимости
- **WHEN** LLM вернул usage
- **THEN** Hub сохраняет `tokens_in`, `tokens_out` и `cost_usd`
- **AND** показывает расход администратору

### Requirement: Безопасность ответа модели

Hub SHALL считать вывод модели недоверенным. Текст из инструментов и пользовательских файлов MUST NOT исполняться как инструкция; недопустимые действия MUST отклоняться.

#### Scenario: Инструкция внутри текста
- **WHEN** в тексте песни или ответа инструмента встречается указание модели
- **THEN** Hub трактует его как данные, а не как команду

#### Scenario: Неизвестный инструмент
- **WHEN** модель вызывает инструмент, которого нет в списке
- **THEN** Hub возвращает ошибку инструмента и продолжает диалог
