## Purpose

Домен описывает получение музыки в HomeMusic: поиск по библиотеке и внешнему каталогу, страницы артистов и альбомов, поиск файлов у провайдеров, очередь загрузок, выбор источника и перенос коллекций из других сервисов. Домен не импортирует файлы в библиотеку напрямую: финальный импорт выполняет `library` через `storage`.

## Requirements

### Requirement: Унифицированный поиск

Hub SHALL объединять результаты поиска по собственной библиотеке и внешнему каталогу. Для внешнего каталога MUST использоваться Deezer; hitmoz MUST использоваться только для кириллических запросов и только если Deezer недоступен или не дал артистов/треков. Ответ MUST содержать признаки владения треками.

#### Scenario: Поиск по библиотеке и каталогу
- **WHEN** пользователь вызывает `GET /api/search?q=...`
- **THEN** Hub возвращает локальные треки, внешних артистов и альбомы, а также первые 25 внешних треков
- **AND** для треков указывает `owned`, `uid`/`library_track_id` и `downloading`
- **AND** ответ не содержит полей-алиасов внешнего медиасервера

#### Scenario: Продолжение списка треков
- **WHEN** клиент передаёт `offset` в `GET /api/search/tracks`
- **THEN** Hub возвращает следующую страницу внешних треков и `next_offset`
- **AND** `next_offset: null` означает конец списка

#### Scenario: Ошибка Deezer
- **WHEN** Deezer не отвечает при постраничном поиске
- **THEN** Hub возвращает `502`

#### Scenario: Fallback hitmoz
- **WHEN** Deezer недоступен, а запрос содержит кириллицу
- **THEN** Hub дополняет результаты hitmoz

#### Scenario: Латинский запрос без Deezer
- **WHEN** Deezer недоступен, а запрос не содержит кириллицы
- **THEN** Hub возвращает только локальные результаты и ошибки, без hitmoz-фолбэка

### Requirement: История поиска

Hub SHALL хранить последние 30 уникальных запросов пользователя без учёта регистра. Повтор запроса MUST перемещать его в начало и обновлять написание. История MUST быть общей для браузера и встроенного приложения.

#### Scenario: Сохранение запроса
- **WHEN** пользователь отправляет запрос длиной от 2 до 512 символов
- **THEN** Hub сохраняет его первым в истории
- **AND** удаляет старые дубликаты без учёта регистра

#### Scenario: Очистка истории
- **WHEN** пользователь вызывает `DELETE /api/search/history`
- **THEN** Hub удаляет историю текущего аккаунта
- **AND** публикует событие `search_history`

#### Scenario: Некорректный запрос
- **WHEN** запрос короче 2 или длиннее 512 символов
- **THEN** Hub возвращает `422`

### Requirement: Поиск файлов у провайдеров

Hub SHALL искать конкретные файлы у hitmoz, hitmos.fm, yt-dlp, re-upload-провайдеров и опционально Soulseek. Найденный файл MUST быть доступен по `ref` вида `file:<provider>:<provider_id>` для прослушивания и загрузки.

#### Scenario: Обычные источники
- **WHEN** пользователь вызывает `/api/search/providers?q=...&group=sources`
- **THEN** Hub возвращает файлы обычных источников с `Candidate`-полями

#### Scenario: Перезаливы
- **WHEN** пользователь вызывает `/api/search/providers?q=...&group=reuploads`
- **THEN** Hub возвращает файлы YouTube- и SoundCloud-перезаливов
- **AND** помечает их `extra.reupload`, `extra.channel`, `extra.original_title` и, если известно, `extra.uncensored`

#### Scenario: Неизвестный файл
- **WHEN** пользователь пытается слушать или скачивать `file:`-ref, который Hub не помнит
- **THEN** Hub возвращает `404` с просьбой повторить поиск

### Requirement: Страницы артиста и альбома

Hub SHALL отдавать страницы артиста и альбома каталога с признаками владения и обложками нужного размера. Для альбома MUST возвращаться полный список треков и `owned_status`.

#### Scenario: Страница артиста
- **WHEN** пользователь открывает `/api/catalog/artist/{ref}`
- **THEN** Hub возвращает артиста и релизы, сгруппированные по типу и отсортированные от новых к старым

#### Scenario: Страница альбома
- **WHEN** пользователь открывает `/api/catalog/album/{ref}`
- **THEN** Hub возвращает альбом, `owned_status` (`full`, `partial`, `none`) и треки с `owned`/`downloading`

#### Scenario: Неизвестный ref
- **WHEN** ref имеет неизвестный источник или id
- **THEN** Hub возвращает `400` или `404`

### Requirement: Создание пакета загрузки

Hub SHALL принимать загрузку отдельных треков, `track_refs`, альбома, дискографии артиста или конкретного файла. Загрузка MAY добавлять треки в существующий или новый плейлист Hub. Для ♥ без скачанного трека MUST поддерживаться `star=true`.

#### Scenario: Загрузка одного трека
- **WHEN** пользователь отправляет `items` с artist/title или выбранным `candidate`
- **THEN** Hub создаёт batch и элементы со статусом `queued`
- **AND** возвращает `batch_id` и число поставленных в очередь

#### Scenario: Загрузка альбома
- **WHEN** пользователь передаёт `album_ref`
- **THEN** Hub создаёт batch с `expanding: true`
- **AND** фоновая задача `expand_batch` создаёт элементы по трекам альбома

#### Scenario: Уже скачивается
- **WHEN** трек уже есть в активной загрузке этого пользователя
- **THEN** Hub не создаёт второй элемент без `force`
- **AND** ♥ может повысить существующую тихую загрузку до видимой

#### Scenario: Загрузка с ♥
- **WHEN** пользователь передаёт `star=true` для одного `track_ref`
- **THEN** Hub ставит трек в очередь
- **AND** после импорта ставит локальный ♥ в Hub
- **AND** не обращается к внешнему сервису

### Requirement: Жизненный цикл загрузки

Hub SHALL вести загрузку через статусы `queued`, `searching`, `downloading`, `tagging`, `importing`, `done`, `failed`, `needs_review`, `cancelled`. При отсутствии подходящего файла MUST возвращаться `needs_review` с кандидатами для выбора или ссылкой на страницу трека.

#### Scenario: Успешная загрузка
- **WHEN** найден и проверен подходящий файл
- **THEN** Hub скачивает его, тегирует и импортирует в библиотеку
- **AND** после фиксации блоба и записи каталога элемент становится `done` и получает `library_track_id` и `uid`

#### Scenario: Нужен выбор пользователя
- **WHEN** ни один кандидат не прошёл проверку или нет каталожной записи
- **THEN** элемент получает `needs_review`
- **AND** `GET /api/downloads/{id}` возвращает кандидатов

#### Scenario: Повтор с кандидатом или URL
- **WHEN** пользователь вызывает retry с `candidate_index` или `url`
- **THEN** Hub создаёт новую попытку загрузки с выбранным файлом

#### Scenario: Отмена до обработки
- **WHEN** пользователь отменяет загрузку, которую воркер ещё не начал
- **THEN** элемент получает `cancelled`
- **AND** задача не начинает обработку

#### Scenario: Отмена во время обработки
- **WHEN** пользователь отменяет загрузку, которую воркер уже выполняет
- **THEN** API выставляет `cancelled`, но воркер не проверяет статус в середине работы
- **AND** уже идущая загрузка MAY завершиться и перезаписать статус на `done`/`importing`
- **AND** временные файлы очищаются в `finally` задачи

#### Scenario: Очистка завершённых
- **WHEN** пользователь вызывает `POST /api/downloads/clear`
- **THEN** Hub удаляет `done` и `cancelled` элементы, кроме нужных как якоря порядка плейлиста

### Requirement: Выбор источника и порядок провайдеров

Hub SHALL выбирать источник по порядку из `config.yaml`. Для русских треков MUST использоваться русский порядок источников; для остальных — обычный. Явный русский трек MUST сначала искать копию, известную как «без цензуры», и только потом допускать возможную цензуру с предупреждением.

#### Scenario: Русский трек
- **WHEN** запрос содержит кириллицу, CIS-релиз или `lang=ru`
- **THEN** Hub использует `sources.ru`
- **AND** для явного трека применяет правила uncensored/re-upload

#### Scenario: Обычный трек
- **WHEN** запрос не является русским
- **THEN** Hub использует `sources.default`
- **AND** после обычных источников MAY использовать `sources.download_fallback`

#### Scenario: Soulseek включён
- **WHEN** в `.env` заданы все параметры Soulseek
- **THEN** загрузка библиотеки сначала пробует Soulseek по правилам `soulseek.format`
- **AND** прослушивание Soulseek не использует

### Requirement: Импорт коллекции из сервиса

Hub SHALL импортировать коллекцию пользователя из Yandex Music или Spotify export. Импорт MUST проходить этапы авторизации/чтения snapshot, предпросмотра, сопоставления и применения, а результат MUST сохраняться в `source_map` для повторного использования.

#### Scenario: Импорт Yandex по коду
- **WHEN** пользователь выбирает вход по коду и подтверждает его на стороне Yandex
- **THEN** Hub получает токен, читает коллекцию и создаёт `Import` со snapshot

#### Scenario: Импорт Spotify export
- **WHEN** пользователь загружает архив Spotify export
- **THEN** Hub читает плейлисты и сохранённую музыку без OAuth Spotify

#### Scenario: Предпросмотр и выбор коллекций
- **WHEN** snapshot загружен
- **THEN** Hub возвращает коллекции и статистику
- **AND** пользователь может выбрать коллекции, режим `economy`/`full` и скачивание альбомов

#### Scenario: Сопоставление
- **WHEN** импорт запущен
- **THEN** Hub сопоставляет элементы с библиотекой и каталогом
- **AND** присваивает `owned`, `exact`, `probable` или `not_found`

#### Scenario: Применение
- **WHEN** элемент сопоставлен
- **THEN** Hub ставит локальный ♥, переписывает плейлисты Hub и/или ставит загрузку с низким приоритетом
- **AND** повторный импорт использует `source_map` и не ищет те же элементы заново

#### Scenario: Ручной выбор элемента импорта
- **WHEN** пользователь выбирает кандидата или пропускает элемент
- **THEN** Hub сохраняет решение и продолжает импорт

#### Scenario: Отмена импорта
- **WHEN** пользователь отменяет импорт
- **THEN** Hub прекращает обработку и помечает импорт отменённым
