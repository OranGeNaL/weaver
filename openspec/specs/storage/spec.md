## Purpose

Домен описывает физическое хранение медиафайлов: раскладку `MUSIC_ROOT`, безопасные пути, staging, корзину, атомарные перемещения, проверку файлов и временные копии для прослушивания. Домен не владеет метаданными альбомов и треков и не обращается к Navidrome.

## Requirements

### Requirement: Раскладка библиотеки

Hub SHALL хранить файлы библиотеки в `MUSIC_ROOT/library` по схеме `{AlbumArtist}/{Year - Album}/{Disc}-{NN} - {Title}.{ext}`. Компоненты пути MUST очищаться от недопустимых символов, пробелов и зарезервированных имён.

#### Scenario: Новый трек альбома
- **WHEN** файл импортируется в альбом с исполнителем, годом, номером диска и трека
- **THEN** файл размещается по предсказуемому пути внутри `library/`
- **AND** кириллица и Unicode сохраняются в имени

#### Scenario: Неизвестный год
- **WHEN** у альбома нет года
- **THEN** каталог альбома называется только по названию альбома

#### Scenario: Опасное имя
- **WHEN** название содержит `..`, `/`, `\`, управляющие символы или зарезервированное имя вроде `CON`
- **THEN** компонент пути очищается и не выходит за пределы библиотеки

### Requirement: Атомарное перемещение файла

Hub SHALL перемещать готовый файл из staging в библиотеку через `os.replace` в пределах одной файловой системы. Если `os.replace` завершается `OSError`, Hub MUST использовать `shutil.move`; в этом случае атомарность не гарантируется.

#### Scenario: Успешный импорт в одной ФС
- **WHEN** staging и library находятся на одной файловой системе
- **THEN** Hub атомарно перемещает файл в целевую папку альбома
- **AND** запись `tracks` создаётся после перемещения

#### Scenario: Ошибка os.replace
- **WHEN** `os.replace` завершается `OSError`
- **THEN** Hub пробует `shutil.move`
- **AND** при обрыве копирования в библиотеке MAY остаться частичный файл

#### Scenario: Ошибка перемещения
- **WHEN** перемещение завершается ошибкой
- **THEN** файл остаётся в staging или удаляется как временный

### Requirement: Уникальные имена и версии

Hub SHALL не перезаписывать существующий файл. При совпадении имени MUST использоваться уникальный суффикс, а при явной повторной загрузке — версия `[vN]`.

#### Scenario: Совпадение имени
- **WHEN** в каталоге уже есть файл с таким именем
- **THEN** новый файл получает суффикс ` (2)`, ` (3)` или следующий свободный

#### Scenario: Повторная загрузка версии
- **WHEN** пользователь явно скачивает другую версию уже имеющегося трека
- **THEN** новая версия сохраняется рядом с существующей с суффиксом `[vN]`
- **AND** старая версия не перезаписывается

### Requirement: Staging загрузок и импорта

Hub SHALL использовать `MUSIC_ROOT/staging` для временных файлов загрузок, скачиваний и серверных копий. Каталог элемента загрузки MUST удаляться в `finally` при завершении задачи; ежедневная очистка MUST покрывать только `staging/uploads`. Каталоги `staging/dl/*`, оставшиеся после аварийного завершения контейнера, автоматически не очищаются.

#### Scenario: Скачивание трека
- **WHEN** запущена загрузка трека
- **THEN** файл сохраняется в отдельный staging-каталог элемента
- **AND** каталог удаляется в `finally` после завершения задачи

#### Scenario: Аварийное завершение
- **WHEN** контейнер завершился во время загрузки
- **THEN** каталог `staging/dl/<item_id>` MAY остаться до ручной очистки

#### Scenario: Загрузка своего файла
- **WHEN** пользователь загружает файл через `/api/uploads`
- **THEN** файл сохраняется в `staging/uploads/<user_id>/`
- **AND** при отмене или ошибке временный файл удаляется

#### Scenario: Устаревшие uploads
- **WHEN** файл uploads остаётся в staging дольше установленного срока
- **THEN** ежедневный housekeeping удаляет его

### Requirement: Корзина и срок хранения

Hub SHALL перемещать удалённые треки в `MUSIC_ROOT/.trash/<дата>/`, а не удалять их сразу. Корзина MUST очищаться по `library.trash_days`.

#### Scenario: Удаление трека
- **WHEN** пользователь удаляет трек
- **THEN** файл перемещается в `.trash/` с сохранением возможности восстановления
- **AND** запись трека удаляется из активной библиотеки

#### Scenario: Очистка корзины
- **WHEN** файл находится в корзине дольше `trash_days`
- **THEN** housekeeping удаляет его

### Requirement: Проверка медиафайла

Hub SHALL пытаться прочитать аудиофайл через ffprobe и MUST сохранять длительность, битрейт и кодек, когда проверка удалась. Для скачанных файлов неудачная проверка или несовпадение длительности MUST отклонять кандидата; для загруженных пользователем файлов ошибка ffprobe MUST логироваться, но импорт MAY продолжаться без этих полей.

#### Scenario: Корректный файл
- **WHEN** ffprobe читает аудиофайл
- **THEN** Hub сохраняет длительность, битрейт и кодек
- **AND** файл допускается к импорту

#### Scenario: Повреждённый файл при скачивании
- **WHEN** postcheck не может прочитать скачанный файл или длительность не совпадает
- **THEN** кандидат отклоняется
- **AND** файл удаляется из staging

#### Scenario: Ошибка ffprobe при загрузке пользователем
- **WHEN** ffprobe не может прочитать загруженный файл
- **THEN** Hub логирует предупреждение
- **AND** импортирует файл без длительности, битрейта и кодека

#### Scenario: Подозрительная тишина
- **WHEN** postcheck находит длинную тишину
- **THEN** трек импортируется с предупреждением

### Requirement: Временные копии для прослушивания

Hub SHALL хранить серверные копии файлов для `listen` в `staging/listen` и лёгкие Opus-копии в `staging/listen-light`. Копии MUST иметь ограничение по размеру/сроку и вытесняться по давности использования.

#### Scenario: Поток из YouTube
- **WHEN** googlevideo-файл нельзя отдать напрямую
- **THEN** Hub скачивает серверную копию в `staging/listen`
- **AND** отдаёт клиенту Range-запросы по мере роста копии

#### Scenario: Лёгкий вариант
- **WHEN** клиент запрашивает `q=mobile` для тяжёлого файла
- **THEN** Hub отдаёт Opus-копию из `staging/listen-light`, если она готова
- **AND** иначе отдаёт оригинал с заголовком `X-HomeMusic-Variant: original-pending`

#### Scenario: Переполнение кэша
- **WHEN** суммарный размер копий превышает лимит
- **THEN** Hub удаляет копии, которые дольше всего не использовались

### Requirement: Отчёт о свободном месте

Hub SHALL сообщать свободное место в статистике импорта, чтобы клиент мог предупредить пользователя. Автоматической блокировки операций по свободному месту нет.

#### Scenario: Предпросмотр импорта
- **WHEN** пользователь открывает предпросмотр импорта
- **THEN** Hub возвращает `free_bytes` для `MUSIC_ROOT`
- **AND** клиент MAY показать предупреждение о нехватке места
