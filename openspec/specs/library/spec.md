## Purpose

Домен описывает собственный каталог HomeMusic: альбомы, треки и ленивые артисты, теги, обложки, загрузку своих файлов, правки библиотеки, сверку каталога, плейлисты Navidrome и переходный прокси библиотеки для PWA. Публичный идентификатор каталога — `uid`; `/api/nd/*` остаётся deprecated до этапа 7. Физические файлы принадлежат домену `storage`, а каталог Hub — источник истины для альбомов, треков и артистов.

## Requirements

### Requirement: Список и поиск альбомов библиотеки

Hub SHALL отдавать пользователю список альбомов Hub с количеством треков и наличием обложки. Поиск по `q` MUST нормализовать регистр, `ё` и пунктуацию. Список MUST поддерживать `sort` (`recent`, `frequent`, `newest`, `starred`, `alphabeticalByName`, `alphabeticalByArtist`, `random`) и пагинацию с лимитом 200.

#### Scenario: Список альбомов
- **WHEN** пользователь вызывает `GET /api/library/albums`
- **THEN** Hub возвращает альбомы в порядке `sort` (по умолчанию до этапа 6 — `updated_at`; значение `updated_at` доступно явно)
- **AND** с `track_count` и `has_cover`

#### Scenario: Поиск по названию
- **WHEN** пользователь передаёт `q`
- **THEN** Hub ищет по нормализованному `album_artist + title`
- **AND** возвращает только совпавшие альбомы

#### Scenario: Пагинация
- **WHEN** пользователь передаёт `offset` и `limit`
- **THEN** Hub возвращает соответствующую страницу, не более 200 альбомов

### Requirement: Создание и просмотр альбома

Hub SHALL создавать альбом Hub с собственным `uid`, названием, исполнителем альбома, годом, жанром, типом релиза и ссылкой на артиста. Просмотр альбома MUST возвращать его треки в порядке диска и номера трека.

#### Scenario: Создание альбома
- **WHEN** пользователь вызывает `POST /api/library/albums` с title и album_artist
- **THEN** Hub создаёт `Album` с новым `uid` и связью с артистом
- **AND** возвращает его с треками

#### Scenario: Неизвестный артист
- **WHEN** альбом создаётся с новым `album_artist`
- **THEN** Hub создаёт ленивую сущность артиста
- **AND** связывает с ней альбом

#### Scenario: Просмотр альбома
- **WHEN** пользователь вызывает `GET /api/library/albums/{uid}`
- **THEN** Hub возвращает альбом и его треки, отсортированные по `disc_no`, `track_no`, `id`

#### Scenario: Неизвестный альбом
- **WHEN** альбома с таким `uid` нет
- **THEN** Hub возвращает `404`

### Requirement: Правка альбома и треков

Hub SHALL обновлять метаданные альбома и трека, перемещать треки между альбомами, объединять альбомы и удалять треки в корзину. При перемещении и переименовании Hub MUST сохранять стабильные `uid` и MUST NOT требовать повторного сканирования или перепривязки к Navidrome.

#### Scenario: Переименование альбома
- **WHEN** пользователь меняет название или исполнителя альбома
- **THEN** Hub обновляет метаданные в БД
- **AND** публикует событие `library` с `kind: "changed"` и `album_id`

#### Scenario: Перемещение треков
- **WHEN** пользователь передаёт `track_ids`/`uids` и целевой `album_id`/`album_uid`
- **THEN** Hub переносит треки в целевой альбом
- **AND** пустые исходные альбомы удаляются

#### Scenario: Слияние альбомов
- **WHEN** пользователь передаёт `source_ids`/`uids` и `target_id`/`target_uid`
- **THEN** Hub переносит треки исходных альбомов в целевой
- **AND** возвращает целевой альбом

#### Scenario: Удаление трека
- **WHEN** пользователь вызывает `DELETE /api/library/tracks/{uid}` (или legacy `{id}`)
- **THEN** у трека выставляется `deleted_at`, а блоб — кандидат в корзину
- **AND** пустой альбом удаляется

### Requirement: Обложки альбомов

Hub SHALL принимать изображение обложки до 20 МБ, сохранять его как блоб S3 и связывать с альбомом. Hub MUST отдавать обложку по `uid` альбома с ресайзом и fallback на встроенную обложку трека.

#### Scenario: Загрузка обложки
- **WHEN** пользователь отправляет изображение в `PUT /api/library/albums/{uid}/cover`
- **THEN** Hub сохраняет блоб обложки и связывает его с альбомом
- **AND** возвращает альбом с `has_cover: true`

#### Scenario: Слишком большая картинка
- **WHEN** размер изображения больше 20 МБ
- **THEN** Hub возвращает `413`

#### Scenario: Получение обложки
- **WHEN** пользователь запрашивает `GET /api/library/albums/{uid}/cover?size=...` (или legacy `{id}`)
- **THEN** Hub отдаёт обложку из кэша или S3
- **AND** при `size` возвращает уменьшенный JPEG
- **AND** при отсутствии обложки возвращает `404`

### Requirement: Загрузка своих файлов

Hub SHALL принимать аудиофайлы разрешённых форматов, сохранять их в staging и создавать запись `Upload` со статусом `uploaded`. Импорт MUST выполняться только после явного `commit` с выбранным альбомом и метаданными треков; после импорта файл MUST стать блобом S3.

#### Scenario: Загрузка файла
- **WHEN** пользователь отправляет файл разрешённого расширения
- **THEN** Hub сохраняет его в `staging/uploads/<user_id>/`
- **AND** читает теги и возвращает `UploadOut`

#### Scenario: Неподдерживаемый формат
- **WHEN** расширение файла не входит в `uploads.extensions`
- **THEN** Hub возвращает `415`

#### Scenario: Слишком большой файл
- **WHEN** файл больше `uploads.max_file_mb`
- **THEN** Hub удаляет временный файл и возвращает `413`

#### Scenario: Импорт загруженных файлов
- **WHEN** пользователь вызывает `POST /api/uploads/commit` с существующим или новым альбомом
- **THEN** Hub импортирует выбранные файлы в библиотеку как блобы
- **AND** помечает `Upload` как `imported`
- **AND** публикует `library {kind: "imported"}`

#### Scenario: Отмена загрузки
- **WHEN** пользователь удаляет незакоммиченную загрузку
- **THEN** файл удаляется из staging, статус становится `discarded`

### Requirement: Прокси библиотеки Navidrome

До этапа 6 Hub SHALL сохранять `/api/nd/*` как deprecated-совместимый слой. Для пользователя с ND-кредами он MAY проксировать Navidrome; для пользователя без ND-кредов (созданного после этапа 4) он MUST отдавать ND-совместимую форму из Hub-каталога `/api/library/*`, а не `409`. Ошибки MUST преобразовываться в `404`/`403`/`502`.

#### Scenario: Главная библиотеки
- **WHEN** старая PWA вызывает `GET /api/nd/home`
- **THEN** Hub возвращает недавние, частые, новые и любимые альбомы и артистов
- **AND** для пользователя без ND-кредов данные берутся из Hub-каталога

#### Scenario: Плейлист другого пользователя
- **WHEN** запрошен чужой плейлист и доступа нет
- **THEN** Hub возвращает `403`

#### Scenario: Navidrome недоступен
- **WHEN** прокси к Navidrome завершается сетевой ошибкой
- **THEN** Hub возвращает `502` с русским сообщением

#### Scenario: Новый клиент
- **WHEN** клиент знает `hub_library_v1`
- **THEN** он использует `/api/library/*`
- **AND** не зависит от `/api/nd/*`

### Requirement: Плейлисты Hub

Hub SHALL создавать, читать, изменять и удалять плейлисты Hub от имени владельца. Плейлист MUST быть упорядоченным списком элементов; дубликаты MUST быть допустимы; у элемента MUST быть `uid` и якорь (`anchor_uid` — uid соседнего элемента) для вставки фоновыми задачами. Список MUST показывать плейлисты текущего пользователя и его системные плейлисты (у системных `owner_id` задан владельцем); чужие системные плейлисты не показываются.

#### Scenario: Список плейлистов
- **WHEN** пользователь вызывает `GET /api/playlists`
- **THEN** Hub возвращает плейлисты, владельцем которых он является
- **AND** добавляет его системные плейлисты (`system=true`, `owner_id` = он)

#### Scenario: Плейлист без владельца
- **WHEN** системный плейлист (например, «Микс дня») принадлежит другому пользователю
- **THEN** Hub его не показывает

#### Scenario: Создание плейлиста
- **WHEN** пользователь передаёт непустое название
- **THEN** Hub создаёт плейлист Hub с `uid` и возвращает его

#### Scenario: Добавление треков
- **WHEN** пользователь передаёт `uids`, `song_ids` (deprecated) или `library_track_ids`
- **THEN** Hub добавляет существующие треки в плейлист
- **AND** если ни один трек ещё не импортирован, возвращает `400`

#### Scenario: Удаление по позициям
- **WHEN** пользователь передаёт `indexes`
- **THEN** Hub удаляет элементы с этими позициями, включая повторяющиеся

#### Scenario: Переупорядочивание
- **WHEN** пользователь передаёт новый порядок элементов
- **THEN** Hub сохраняет позиции и порядок

#### Scenario: Вставка по якорю
- **WHEN** фоновая задача добавляет трек, у которого задан якорь
- **THEN** трек встаёт рядом с якорем, а не в конец плейлиста
- **AND** параллельные вставки не теряют элементы

### Requirement: Избранное для PWA

Hub SHALL сохранять контракт `/api/starred`: `song_ids`, `album_ids`, `artist_ids` (где известны), `refs` (включая pending/catalog-only) и `subjects` с provenance; добавлять `track_uids`. Capability `hub_liked_v1` MUST сообщать клиенту, что источник — Hub.

#### Scenario: Список избранного
- **WHEN** пользователь вызывает `GET /api/starred`
- **THEN** Hub возвращает `song_ids`/`album_ids`/`artist_ids`, `refs`, `subjects` и `track_uids`
- **AND** не обращается к Navidrome

#### Scenario: Новый клиент
- **WHEN** клиент видит `hub_liked_v1`
- **THEN** он MAY использовать `track_uids`
- **AND** старый клиент продолжает использовать `song_ids`

### Requirement: Любимые в каталоге Hub

Hub SHALL отдавать `GET /api/library/liked` — треки, альбомы и артистов с ♥ пользователя, объединяя собственные решения и импортированные ♥. Собственное решение MUST переопределять импортированное, а отмена ♥ MUST сразу убирать объект из ответа.

#### Scenario: Список любимых
- **WHEN** пользователь вызывает `GET /api/library/liked`
- **THEN** Hub возвращает треки, альбомы и артистов с ♥
- **AND** элементы отсортированы от новых к старым

#### Scenario: Отмена ♥
- **WHEN** пользователь снимает ♥ с трека
- **THEN** трек исчезает из `/api/library/liked`

#### Scenario: Импортированный ♥
- **WHEN** ♥ пришёл из импорта сервиса
- **THEN** он отображается в списке с `provenance: "import"`
- **AND** собственное решение пользователя имеет приоритет

#### Scenario: Пустой список
- **WHEN** у пользователя нет ♥
- **THEN** Hub возвращает пустые массивы
- **AND** не обращается к внешнему сервису

### Requirement: События изменения библиотеки

Hub SHALL после правок библиотеки фиксировать изменения каталога и публиковать событие `library` текущему пользователю. `catalog_commit` MUST сохранять Hub-side effects `nd_scan` (`imports_done`, `mixes_done`) через `nd_sync` до этапа 5; ND-записи (`star_liked`, `sync_likes`, `sync_playlists`, `process_playlist_adds`) MUST быть инертны без `nd_song_id`/кредов и не считаться ошибкой; повторное сканирование Navidrome MUST NOT требоваться.

#### Scenario: Правка завершена
- **WHEN** альбом, трек или обложка изменены
- **THEN** Hub обновляет каталог и ставит задачу сверки при необходимости
- **AND** публикует `library` с `kind: "changed"` и `album_id`

#### Scenario: Импорт завершён
- **WHEN** загруженные файлы импортированы
- **THEN** Hub публикует `library` с `kind: "imported"` и `album_id`
- **AND** `nd_sync` выполняет `imports_done`/`mixes_done`; ND-линковка — no-op без кредов

### Requirement: Каталог Hub

Hub SHALL отдавать каталог библиотеки по `/api/library/*`: главную (недавние, частые, новые и любимые альбомы), альбомы с сортировками, артистов, артиста, альбом и трек. Сортировки MUST включать `recent`, `frequent`, `newest`, `starred`, `alphabeticalByName`, `alphabeticalByArtist`, `random`.

#### Scenario: Главная каталога
- **WHEN** пользователь вызывает `GET /api/library/home`
- **THEN** Hub возвращает недавние, частые, новые и любимые альбомы и артистов
- **AND** «любимые» — свёртка решений `play_events` kind like/unlike (как `favorites.snapshot`); `favorite_subjects` хранит только алиасы/метаданные; при отсутствии данных список пуст

#### Scenario: Список альбомов
- **WHEN** пользователь вызывает `GET /api/library/albums?sort=alphabeticalByName`
- **THEN** Hub возвращает альбомы в запрошенном порядке
- **AND** поддерживает пагинацию с лимитом 200
- **AND** дефолт до этапа 6 — `updated_at`
- **AND** deprecated `type` MAY приниматься как алиас `sort`

#### Scenario: Артист и альбом
- **WHEN** пользователь открывает артиста или альбом по `uid`
- **THEN** Hub возвращает сущность и её альбомы/треки в порядке диска и номера

#### Scenario: Неизвестный объект
- **WHEN** `uid` не существует
- **THEN** Hub возвращает `404`

### Requirement: Публичные идентификаторы

Hub SHALL использовать `uid` (UUID) как публичный идентификатор трека, альбома и артиста для новых endpoint'ов и полей. До этапа 7 переходный слой MUST принимать deprecated `int` (`id`, `album_id`, `track_id`) и MAY возвращать `nd_*`, чтобы текущая PWA не ломалась; новые поля MUST быть только `uid`. `int`-приём действует до этапа 7 включительно.

#### Scenario: Ответ каталога
- **WHEN** клиент получает трек, альбом или артиста
- **THEN** новые поля идентификаторов — `uid`
- **AND** deprecated `int`/`nd_*` MAY присутствовать до этапа 7

#### Scenario: Ссылка в PWA
- **WHEN** PWA открывает `/lib/album/<uid>`
- **THEN** Hub находит альбом по `uid`

#### Scenario: Старый int-ID
- **WHEN** PWA вызывает `/api/library/albums/{int}`
- **THEN** Hub находит тот же альбом по legacy `id`

### Requirement: Ленивые артисты

Hub SHALL создавать сущность артиста при первом появлении в импорте или правке. `name_norm = normalize_artist(name).latin or .text` MUST быть уникальным и непустым (`CHECK (name_norm <> '')`); создание — через upsert. UNIQUE склеивает однофамильцев — осознанный компромисс, разделение — отдельная операция. Строки `tracks.artist` и `albums.album_artist` MUST оставаться для отображения кредитов. Переименование артиста MUST быть отдельной операцией слияния.

#### Scenario: Первый трек артиста
- **WHEN** импортируется трек с новым исполнителем
- **THEN** создаётся `artists` с новым `uid`
- **AND** альбом и трек ссылаются на него

#### Scenario: Существующий артист
- **WHEN** импортируется трек с уже известным нормализованным именем
- **THEN** используется существующая сущность
- **AND** новый артист не создаётся

#### Scenario: Слияние артистов
- **WHEN** пользователь объединяет двух артистов
- **THEN** альбомы и треки переносятся на целевого
- **AND** исходная сущность удаляется

#### Scenario: Параллельный импорт
- **WHEN** два импорта одновременно создают артиста с одним `name_norm`
- **THEN** создаётся одна сущность
- **AND** второй импорт использует её

### Requirement: Сверка каталога и блобов

Hub SHALL периодически (housekeeping) сверять БД и S3: трек без блоба, блоб без ссылок, осиротевшая обложка. Сверка MUST NOT индексировать новые объекты в бакете и MUST NOT удалять блобы: `tracks.integrity_issue` хранит `missing_blob`, `albums.integrity_issue` — `missing_cover`, `orphan_blob` сообщается в health/лог (или `blobs.integrity_issue`); признаки сбрасываются при успешной сверке; удаление остаётся за GC домена `storage`.

#### Scenario: Блоб без ссылок
- **WHEN** блоб не имеет ссылок из треков или альбомов
- **THEN** сверка выставляет `orphan_blob` и сообщает о нём
- **AND** удаляет его storage GC позже, не сверкой

#### Scenario: Трек без блоба
- **WHEN** трек ссылается на отсутствующий блоб
- **THEN** Hub выставляет `missing_blob`
- **AND** сообщает об этом в лог и health
- **AND** сбрасывает признак при успешной сверке

#### Scenario: Объект вне Hub
- **WHEN** в бакете появился объект, которого нет в БД
- **THEN** сверка его не индексирует
- **AND** MAY сообщить о нём администратору
