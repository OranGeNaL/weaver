## Purpose

Домен описывает собственную библиотеку HomeMusic: альбомы и треки, теги, обложки, загрузку своих файлов, правки библиотеки, плейлисты Navidrome и прокси-представление библиотеки для PWA. Физические файлы принадлежат домену `storage`, а Navidrome остаётся источником истины для пользовательских плейлистов и звёзд.

## Requirements

### Requirement: Список и поиск альбомов библиотеки

Hub SHALL отдавать пользователю список альбомов Hub с количеством треков и наличием обложки. Поиск по `q` MUST нормализовать регистр, `ё` и пунктуацию.

#### Scenario: Список альбомов
- **WHEN** пользователь вызывает `GET /api/library/albums`
- **THEN** Hub возвращает альбомы, отсортированные по `updated_at`, с `track_count` и `has_cover`

#### Scenario: Поиск по названию
- **WHEN** пользователь передаёт `q`
- **THEN** Hub ищет по нормализованному `album_artist + title`
- **AND** возвращает только совпавшие альбомы

#### Scenario: Пагинация
- **WHEN** пользователь передаёт `offset` и `limit`
- **THEN** Hub возвращает соответствующую страницу, не более 200 альбомов

### Requirement: Создание и просмотр альбома

Hub SHALL создавать альбом Hub с собственным `uid`, названием, исполнителем альбома, годом, жанром и типом релиза. Просмотр альбома MUST возвращать его треки в порядке диска и номера трека.

#### Scenario: Создание альбома
- **WHEN** пользователь вызывает `POST /api/library/albums` с title и album_artist
- **THEN** Hub создаёт `Album` с новым `uid` и возвращает его с треками

#### Scenario: Просмотр альбома
- **WHEN** пользователь вызывает `GET /api/library/albums/{id}`
- **THEN** Hub возвращает альбом и его треки, отсортированные по `disc_no`, `track_no`, `id`

#### Scenario: Неизвестный альбом
- **WHEN** альбома с таким id нет
- **THEN** Hub возвращает `404`

### Requirement: Правка альбома и треков

Hub SHALL обновлять метаданные альбома и трека, перемещать треки между альбомами, объединять альбомы и удалять треки в корзину. При перемещении и переименовании Hub MUST сохранять стабильные `HOMEMUSIC_TRACK_ID` / `HOMEMUSIC_ALBUM_ID` и перепривязывать `nd_song_id` после сканирования.

#### Scenario: Переименование альбома
- **WHEN** пользователь меняет название или исполнителя альбома
- **THEN** Hub перетегирует и перемещает файлы треков в новый каталог
- **AND** запускает `nd_scan` и публикует событие `library`

#### Scenario: Перемещение треков
- **WHEN** пользователь передаёт `track_ids` и целевой `album_id`
- **THEN** Hub переносит треки в целевой альбом
- **AND** пустые исходные альбомы удаляются

#### Scenario: Слияние альбомов
- **WHEN** пользователь передаёт `source_ids` и `target_id`
- **THEN** Hub переносит треки исходных альбомов в целевой
- **AND** возвращает целевой альбом

#### Scenario: Удаление трека
- **WHEN** пользователь вызывает `DELETE /api/library/tracks/{id}`
- **THEN** файл перемещается в `.trash/`, запись трека удаляется
- **AND** пустой альбом удаляется

### Requirement: Обложки альбомов

Hub SHALL принимать изображение обложки до 20 МБ, сохранять его как `cover.jpg` в каталоге альбома и встраивать в теги треков. Hub MUST отдавать обложку с возможностью ресайза и fallback на встроенную обложку трека.

#### Scenario: Загрузка обложки
- **WHEN** пользователь отправляет изображение в `PUT /api/library/albums/{id}/cover`
- **THEN** Hub готовит JPEG, сохраняет `cover.jpg` и обновляет теги треков
- **AND** возвращает альбом с `has_cover: true`

#### Scenario: Слишком большая картинка
- **WHEN** размер изображения больше 20 МБ
- **THEN** Hub возвращает `413`

#### Scenario: Получение обложки
- **WHEN** пользователь запрашивает `GET /api/library/albums/{id}/cover?size=...`
- **THEN** Hub отдаёт `cover.jpg` или встроенную обложку
- **AND** при `size` возвращает уменьшенный JPEG
- **AND** при отсутствии обложки возвращает `404`

### Requirement: Загрузка своих файлов

Hub SHALL принимать аудиофайлы разрешённых форматов, сохранять их в staging и создавать запись `Upload` со статусом `uploaded`. Импорт MUST выполняться только после явного `commit` с выбранным альбомом и метаданными треков.

#### Scenario: Загрузка файла
- **WHEN** пользователь отправляет файл разрешённого расширения
- **THEN** Hub сохраняет его в `staging/uploads/<user_id>/`
- **AND** читает теги и возвращает `UploadOut`

#### Scenario: Неподдерживаемый формат
- **WHEN** расширение файла не входит в `uploads.extensions`
- **THEN** Hub возвращает `415`

#### Scenario: Слишком большой файл
- **WHEN** файл больше `uploads.max_file_mb`
- **THEN** Hub удаляет временный файл и возвращает `413`

#### Scenario: Импорт загруженных файлов
- **WHEN** пользователь вызывает `POST /api/uploads/commit` с существующим или новым альбомом
- **THEN** Hub импортирует выбранные файлы в библиотеку
- **AND** помечает `Upload` как `imported`
- **AND** запускает `nd_scan` и публикует `library {kind: "imported"}`

#### Scenario: Отмена загрузки
- **WHEN** пользователь удаляет незакоммиченную загрузку
- **THEN** файл удаляется из staging, статус становится `discarded`

### Requirement: Прокси библиотеки Navidrome

Hub SHALL предоставлять PWA представление библиотеки Navidrome от имени текущего пользователя: главная, альбомы, артисты, «Понравившиеся» и обложки. Ошибки Navidrome MUST преобразовываться в `404`, `403` или `502`.

#### Scenario: Главная библиотеки
- **WHEN** пользователь вызывает `GET /api/nd/home`
- **THEN** Hub возвращает недавние, частые, новые и любимые альбомы, а также артистов

#### Scenario: Плейлист другого пользователя
- **WHEN** Navidrome отвечает «not authorized»
- **THEN** Hub возвращает `403`

#### Scenario: Navidrome недоступен
- **WHEN** запрос к Navidrome завершается сетевой ошибкой
- **THEN** Hub возвращает `502` с русским сообщением

### Requirement: Плейлисты Navidrome

Hub SHALL создавать, читать, изменять и удалять плейлисты Navidrome от имени пользователя. Список плейлистов MUST показывать плейлисты, у которых `owner` точно совпадает с именем Navidrome пользователя (с учётом регистра), а также плейлисты без `owner`.

#### Scenario: Список плейлистов
- **WHEN** пользователь вызывает `GET /api/playlists`
- **THEN** Hub возвращает плейлисты с точным `owner`, равным имени пользователя

#### Scenario: Плейлист без владельца
- **WHEN** Navidrome вернул плейлист без поля `owner`
- **THEN** Hub включает его в список текущего пользователя

#### Scenario: Создание плейлиста
- **WHEN** пользователь передаёт непустое название
- **THEN** Hub создаёт плейлист в Navidrome и возвращает его

#### Scenario: Добавление треков
- **WHEN** пользователь передаёт `song_ids` или `library_track_ids`
- **THEN** Hub добавляет существующие в Navidrome песни в плейлист
- **AND** если ни одна песня ещё не появилась в Navidrome, возвращает `400`

#### Scenario: Удаление по позициям
- **WHEN** пользователь передаёт `indexes`
- **THEN** Hub удаляет песни с этими позициями, включая повторяющиеся

### Requirement: События изменения библиотеки

Hub SHALL после правок библиотеки запускать коалесцированное сканирование Navidrome и публиковать событие `library` текущему пользователю.

#### Scenario: Правка завершена
- **WHEN** альбом, трек или обложка изменены
- **THEN** Hub ставит задачу `nd_scan`
- **AND** публикует `library` с `kind: "changed"` и `album_id`

#### Scenario: Импорт завершён
- **WHEN** загруженные файлы импортированы
- **THEN** Hub публикует `library` с `kind: "imported"` и `album_id`
