## Purpose

Домен описывает прослушивание музыки: подбор файла до загрузки, потоковую отдачу, лёгкий вариант для мобильной сети, приём событий воспроизведения, историю, ♥, дизлайки и приём скробблов Hub-клиентов. Домен не импортирует треки в библиотеку, если пользователь явно не запросил загрузку.

## Requirements

### Requirement: Подбор файла для прослушивания

Hub SHALL подбирать файл для `GET /api/listen?ref=...` тем же способом, что и загрузка: проверять библиотеку, каталог, порядок источников, длительность и версию. Результат MUST иметь вид `full`, `preview` или `library` и MUST кэшироваться. Библиотечный трек MUST адресоваться только `ref=lib:<uid>`.

#### Scenario: Трек уже в библиотеке
- **WHEN** запрошен `ref=lib:<uid>`, который есть в библиотеке
- **THEN** Hub возвращает `kind: "library"`
- **AND** `uid` заполнен
- **AND** ответ не содержит полей-алиасов внешнего медиасервера

#### Scenario: lib:<uid> в рекомендациях и событиях
- **WHEN** smart shuffle или событие прослушивания получает `lib:<uid>`/`uid`
- **THEN** Hub резолвит `lib:<uid>`/`uid` в `tracks.uid`

#### Scenario: q=mobile
- **WHEN** клиент в лимитной сети запрашивает библиотечный трек
- **THEN** PWA передаёт `q=mobile`
- **AND** Hub отвечает `X-HomeMusic-Variant`

#### Scenario: Старый lib:int
- **WHEN** запрошена legacy-форма ссылки на библиотечный трек (`lib:<int>`)
- **THEN** Hub возвращает `404`

#### Scenario: Полный файл найден
- **WHEN** источник отдаёт подходящий полный файл
- **THEN** Hub возвращает `kind: "full"`, провайдера, битрейт и `stream_url`

#### Scenario: Полного файла нет
- **WHEN** ни один источник не дал полный файл
- **THEN** Hub возвращает `kind: "preview"` с 30-секундным превью Deezer

#### Scenario: Ничего не найдено
- **WHEN** нет ни полного файла, ни превью
- **THEN** Hub возвращает `404` или `502` в зависимости от причины

### Requirement: Предзагрузка выбранных файлов

Hub SHALL принимать список `refs` с экрана пользователя и подбирать для них файлы в фоне. Новая заявка MUST заменять предыдущий список. Фоновая работа MUST уступать пользовательским запросам и загрузкам.

#### Scenario: Предзагрузка списка
- **WHEN** клиент отправляет `POST /api/listen/prefetch` с `refs`
- **THEN** Hub ставит отсутствующие файлы в фоновый подбор
- **AND** возвращает число ещё не готовых `queued`

#### Scenario: Список заменён
- **WHEN** приходит новый список `refs`
- **THEN** Hub прекращает подбор треков, которых больше нет в списке

#### Scenario: Лимит списка
- **WHEN** передано больше 100 `refs`
- **THEN** Hub возвращает `422`

#### Scenario: Ограничение prefetch
- **WHEN** в списке больше `PREFETCH_MAX` (40) треков, ещё не готовых к прослушиванию
- **THEN** Hub предзагружает только первые 40
- **AND** `queued` не превышает 40

### Requirement: Потоковая отдача и Range

Hub SHALL отдавать аудио через `GET /api/listen/stream` с поддержкой `Range` и статусом `206`. Для источников без прямого HTTP-аудио Hub MUST сначала создать серверную копию и MUST продолжать её скачивание при обрыве соединения. Для библиотечного трека Hub MUST отдавать байты из локального hot-cache S3.

#### Scenario: Перемотка
- **WHEN** клиент отправляет `Range`
- **THEN** Hub возвращает запрошенный диапазон и `206`
- **AND** для недостижимого диапазона возвращает `416`

#### Scenario: Файл из библиотеки
- **WHEN** выбран `kind: "library"`
- **THEN** Hub отдаёт блоб через локальный hot-cache
- **AND** при промахе заполняет кэш из S3 и продолжает отдачу
- **AND** возвращает `Accept-Ranges` и `ETag` по `sha256`

#### Scenario: googlevideo
- **WHEN** выбран YouTube-файл
- **THEN** Hub скачивает серверную копию в локальный staging и отдаёт поток из неё
- **AND** при обрыве upstream возобновляет загрузку копии

#### Scenario: Источник без HTTP-аудио
- **WHEN** источник отдаёт HLS или не отдаёт прямой файл
- **THEN** Hub сначала скачивает копию и затем отдаёт её клиенту

### Requirement: Лёгкий вариант для мобильной сети

Hub SHALL поддерживать `q=mobile`: тяжёлый файл MUST отдаваться как Ogg Opus 160 кбит/с, лёгкий — как оригинал. Ответ MUST сообщать фактический вариант через `X-HomeMusic-Variant`.

#### Scenario: Тяжёлый файл
- **WHEN** клиент запрашивает `q=mobile` для файла выше 192 кбит/с
- **THEN** Hub отдаёт Opus-копию с `X-HomeMusic-Variant: light`

#### Scenario: Лёгкий файл
- **WHEN** файл уже не тяжелее порога
- **THEN** Hub отдаёт оригинал с `X-HomeMusic-Variant: original`

#### Scenario: Копия ещё не готова
- **WHEN** Opus-копия не успела создаться
- **THEN** Hub отдаёт оригинал с `X-HomeMusic-Variant: original-pending`
- **AND** завершает копию в фоне

### Requirement: Учёт начала прослушивания

Hub SHALL считать запрос потока с начала прослушиванием, кроме запросов с `X-HomeMusic-Prefetch: 1`. Первое прослушивание трека импорта в режиме `economy` MUST запускать его загрузку.

#### Scenario: Обычный старт
- **WHEN** клиент запрашивает поток без `Range` или с `bytes=0-`
- **THEN** Hub фиксирует начало прослушивания
- **AND** для трека импорта `economy` ставит загрузку в очередь

#### Scenario: Предзагрузка следующего трека
- **WHEN** запрос содержит `X-HomeMusic-Prefetch: 1`
- **THEN** Hub не считает это прослушиванием

### Requirement: Приём событий воспроизведения

Hub SHALL принимать пачки событий `start`, `progress`, `interrupted`, `error`, `skip`, `finish`, `like`, `unlike`, `dislike`, `undislike`. Каждое событие MUST иметь клиентский `event_id`; повторная отправка MUST NOT создавать дубль.

#### Scenario: Успешная пачка
- **WHEN** клиент отправляет до 500 корректных событий
- **THEN** Hub сохраняет их и возвращает `accepted`, `duplicates` и `rejected`

#### Scenario: Повторная отправка
- **WHEN** событие с тем же `event_id` уже сохранено у пользователя
- **THEN** Hub считает его дубликатом и не сохраняет второй раз

#### Scenario: Одно битое событие
- **WHEN** одно событие в пачке не проходит валидацию
- **THEN** Hub отклоняет только его
- **AND** остальные события принимаются

#### Scenario: Чужой пользователь
- **WHEN** `expected_user_id` не совпадает с текущим пользователем
- **THEN** Hub возвращает `409`

#### Scenario: Событие из будущего
- **WHEN** часы клиента ушли вперёд больше чем на час
- **THEN** Hub сохраняет событие со временем получения

### Requirement: Скробблы клиентов

Hub SHALL принимать скробблы от аутентифицированных клиентов Hub и сохранять их как события `finish` с клиентским `event_id`, явным маркером `scrobble=true`/`origin=client`, ключом `track_uid` и указанием клиента. Скробблы MUST дедуплицироваться с собственными событиями приложения по `track_uid` в окне `DEDUP_WINDOW + длительность`; вытесненный скроббл MUST сохраняться с `superseded_scrobble=true`.

#### Scenario: Новый скроббл
- **WHEN** клиент отправляет скроббл трека в Hub
- **THEN** Hub сохраняет его как `finish` с клиентом этого клиента

#### Scenario: Скроббл и событие приложения
- **WHEN** рядом есть собственное событие `finish` того же трека
- **THEN** Hub не создаёт дубль
- **AND** отдаёт предпочтение событию с измеренной длительностью

#### Scenario: Повторная отправка
- **WHEN** клиент повторно отправляет тот же `event_id`
- **THEN** Hub не создаёт второе событие

#### Scenario: Вытеснение скроббла
- **WHEN** рядом есть измеренное событие приложения
- **THEN** скроббл не входит в `counted_listens`
- **AND** сохраняется с `superseded_scrobble=true`

### Requirement: История и сводка прослушивания

Hub SHALL отдавать сводку прослушивания за период в указанной IANA-таймзоне. В `counted_listens` MUST входить измеренное `listened_ms`, перешедшее порог 30 секунд или половину короткого трека, либо не вытесненный скроббл клиента Hub (`scrobble=true`, `superseded_scrobble=false`). Старые `finish` без чекпоинтов учитываются только в `legacy_finish_evidence` и не входят в `counted_listens`.

#### Scenario: Сводка за период
- **WHEN** пользователь вызывает `/api/plays/summary` с корректными датами и таймзоной
- **THEN** Hub возвращает измеренные прослушивания и миллисекунды, счётчики scrobble/legacy, первый наблюдаемый момент, снапшоты треков и `quality`

#### Scenario: Админская история
- **WHEN** администратор хочет дни, источники, heatmap, клиентов, топ-треки и открытия
- **THEN** он использует `GET /api/admin/users/{id}/listening`, а не `/api/plays/summary`

#### Scenario: Неверная таймзона
- **WHEN** таймзона неизвестна
- **THEN** Hub возвращает `422`

#### Scenario: Старая история без чекпоинтов
- **WHEN** у исторической попытки нет `playback_id`/`device_id`
- **THEN** Hub учитывает только событие `finish` как `legacy_finish_evidence`
- **AND** пары `start` + `skip` не учитываются
- **AND** legacy-события не входят в `counted_listens`

#### Scenario: Источник скробблов
- **WHEN** в истории есть скроббл клиента Hub
- **THEN** он учитывается наравне с измеренным прослушиванием
- **AND** не требуется импорт из внешнего сервиса

### Requirement: ♥, дизлайки и импортированные звёзды

Hub SHALL хранить собственные ♥ и дизлайки треков и исполнителей и быть единственным источником истины для них. Импортированные ♥ MUST отображаться как происхождение, но не MUST считаться собственным выбором пользователя для профиля вкуса витрины.

#### Scenario: Поставить ♥
- **WHEN** пользователь отмечает трек, альбом или артиста
- **THEN** Hub сохраняет типизированное решение
- **AND** не синхронизирует звезду с внешним сервисом

#### Scenario: Повтор ♥
- **WHEN** приходит команда ♥ с тем же `event_id`
- **THEN** Hub не создаёт второе событие
- **AND** не переигрывает старое решение

#### Scenario: Снять ♥
- **WHEN** пользователь снимает звезду
- **THEN** Hub фиксирует отмену
- **AND** состояние сразу отражается в `/api/starred`

#### Scenario: Дизлайк трека
- **WHEN** пользователь добавляет трек в дизлайки
- **THEN** Hub сохраняет запись и событие `dislike`
- **AND** повторное добавление того же трека не создаёт дубль

#### Scenario: Дизлайк исполнителя
- **WHEN** пользователь добавляет исполнителя в дизлайки
- **THEN** Hub сохраняет `artist_ref` или `artist_uid` и отображает исполнителя в списке дизлайков

#### Scenario: Импортированный ♥
- **WHEN** звезда пришла из импорта другого сервиса
- **THEN** Hub показывает её как `provenance: "import"`
- **AND** не считает её собственным ♥ для профиля вкуса
