## ADDED Requirements

### Requirement: Скробблы клиентов

Hub SHALL принимать скробблы от аутентифицированных клиентов Hub и сохранять их как события `finish` с клиентским `event_id`, явным маркером `scrobble=true`/`origin=client`, ключом `track_uid` и указанием клиента. Скробблы MUST дедуплицироваться с собственными событиями приложения по `track_uid` в окне `DEDUP_WINDOW + длительность`; вытесненный скроббл MUST сохраняться с `superseded_scrobble=true`.

#### Scenario: Новый скроббл
- **WHEN** клиент отправляет скроббл трека в Hub
- **THEN** Hub сохраняет его как `finish` с клиентом этого клиента

#### Scenario: Скроббл и событие приложения
- **WHEN** рядом есть собственное событие `finish` того же трека
- **THEN** Hub не создаёт дубль
- **AND** отдаёт предпочтение событию с измеренной длительностью

#### Scenario: Повторная отправка
- **WHEN** клиент повторно отправляет тот же `event_id`
- **THEN** Hub не создаёт второе событие

#### Scenario: Вытеснение скроббла
- **WHEN** рядом есть измеренное событие приложения
- **THEN** скроббл не входит в `counted_listens`
- **AND** сохраняется с `superseded_scrobble=true`

## MODIFIED Requirements

### Requirement: История и сводка прослушивания

Hub SHALL отдавать сводку прослушивания за период в указанной IANA-таймзоне. В `counted_listens` MUST входить измеренное `listened_ms`, перешедшее порог 30 секунд или половину короткого трека, либо не вытесненный скроббл клиента Hub (`scrobble=true`, `superseded_scrobble=false`). Старые `finish` без чекпоинтов учитываются только в `legacy_finish_evidence` и не входят в `counted_listens`.

#### Scenario: Сводка за период
- **WHEN** пользователь вызывает `/api/plays/summary` с корректными датами и таймзоной
- **THEN** Hub возвращает измеренные прослушивания и миллисекунды, счётчики scrobble/legacy, первый наблюдаемый момент, снапшоты треков и `quality`

#### Scenario: Админская история
- **WHEN** администратор хочет дни, источники, heatmap, клиентов, топ-треки и открытия
- **THEN** он использует `GET /api/admin/users/{id}/listening`, а не `/api/plays/summary`

#### Scenario: Неверная таймзона
- **WHEN** таймзона неизвестна
- **THEN** Hub возвращает `422`

#### Scenario: Старая история без чекпоинтов
- **WHEN** у исторической попытки нет `playback_id`/`device_id`
- **THEN** Hub учитывает только событие `finish` как `legacy_finish_evidence`
- **AND** пары `start` + `skip` не учитываются
- **AND** legacy-события не входят в `counted_listens`

#### Scenario: Источник скробблов
- **WHEN** в истории есть скроббл клиента Hub
- **THEN** он учитывается наравне с измеренным прослушиванием
- **AND** не требуется импорт из внешнего сервиса

### Requirement: ♥, дизлайки и импортированные звёзды

Hub SHALL хранить собственные ♥ и дизлайки треков и исполнителей и быть единственным источником истины для них. Импортированные ♥ MUST отображаться как происхождение, но не MUST считаться собственным выбором пользователя для профиля вкуса витрины.

#### Scenario: Поставить ♥
- **WHEN** пользователь отмечает трек, альбом или артиста
- **THEN** Hub сохраняет типизированное решение
- **AND** не синхронизирует звезду с внешним сервисом

#### Scenario: Повтор ♥
- **WHEN** приходит команда ♥ с тем же `event_id`
- **THEN** Hub не создаёт второе событие
- **AND** не переигрывает старое решение

#### Scenario: Снять ♥
- **WHEN** пользователь снимает звезду
- **THEN** Hub фиксирует отмену
- **AND** состояние сразу отражается в `/api/starred`

#### Scenario: Дизлайк трека
- **WHEN** пользователь добавляет трек в дизлайки
- **THEN** Hub сохраняет запись и событие `dislike`
- **AND** повторное добавление того же трека не создаёт дубль

#### Scenario: Дизлайк исполнителя
- **WHEN** пользователь добавляет исполнителя в дизлайки
- **THEN** Hub сохраняет `artist_ref` или `artist_uid` и отображает исполнителя в списке дизлайков

#### Scenario: Импортированный ♥
- **WHEN** звезда пришла из импорта другого сервиса
- **THEN** Hub показывает её как `provenance: "import"`
- **AND** не считает её собственным ♥ для профиля вкуса

## REMOVED Requirements

### Requirement: Скробблы Navidrome

**Reason**: Navidrome выводится из проекта; импортировать историю больше не из чего.
**Migration**: Клиенты отправляют скробблы в Hub; исторические данные не переносятся (рабочих инстансов нет).
