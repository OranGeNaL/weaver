## MODIFIED Requirements

### Requirement: Плейлисты Hub

Hub SHALL создавать, читать, изменять и удалять плейлисты Hub от имени владельца. Плейлист MUST быть упорядоченным списком элементов; дубликаты MUST быть допустимы; у элемента MUST быть `uid` и якорь (`anchor_uid` — uid соседнего элемента) для вставки фоновыми задачами. Список MUST показывать плейлисты текущего пользователя и его системные плейлисты (у системных `owner_id` задан владельцем); чужие системные плейлисты не показываются.

#### Scenario: Список плейлистов
- **WHEN** пользователь вызывает `GET /api/playlists`
- **THEN** Hub возвращает плейлисты, владельцем которых он является
- **AND** добавляет его системные плейлисты (`system=true`, `owner_id` = он)

#### Scenario: Плейлист без владельца
- **WHEN** системный плейлист (например, «Микс дня») принадлежит другому пользователю
- **THEN** Hub его не показывает

#### Scenario: Создание плейлиста
- **WHEN** пользователь передаёт непустое название
- **THEN** Hub создаёт плейлист Hub с `uid` и возвращает его

#### Scenario: Добавление треков
- **WHEN** пользователь передаёт `uids`, `song_ids` (deprecated) или `library_track_ids`
- **THEN** Hub добавляет существующие треки в плейлист
- **AND** если ни один трек ещё не импортирован, возвращает `400`

#### Scenario: Удаление по позициям
- **WHEN** пользователь передаёт `indexes`
- **THEN** Hub удаляет элементы с этими позициями, включая повторяющиеся

#### Scenario: Переупорядочивание
- **WHEN** пользователь передаёт новый порядок элементов
- **THEN** Hub сохраняет позиции и порядок

#### Scenario: Вставка по якорю
- **WHEN** фоновая задача добавляет трек, у которого задан якорь
- **THEN** трек встаёт рядом с якорем, а не в конец плейлиста
- **AND** параллельные вставки не теряют элементы

## ADDED Requirements

### Requirement: Избранное для PWA

Hub SHALL сохранять контракт `/api/starred`: `song_ids`, `album_ids`, `artist_ids` (где известны), `refs` (включая pending/catalog-only) и `subjects` с provenance; добавлять `track_uids`. Capability `hub_liked_v1` MUST сообщать клиенту, что источник — Hub.

#### Scenario: Список избранного
- **WHEN** пользователь вызывает `GET /api/starred`
- **THEN** Hub возвращает `song_ids`/`album_ids`/`artist_ids`, `refs`, `subjects` и `track_uids`
- **AND** не обращается к Navidrome

#### Scenario: Новый клиент
- **WHEN** клиент видит `hub_liked_v1`
- **THEN** он MAY использовать `track_uids`
- **AND** старый клиент продолжает использовать `song_ids`

### Requirement: Любимые в каталоге Hub

Hub SHALL отдавать `GET /api/library/liked` — треки, альбомы и артистов с ♥ пользователя, объединяя собственные решения и импортированные ♥. Собственное решение MUST переопределять импортированное, а отмена ♥ MUST сразу убирать объект из ответа.

#### Scenario: Список любимых
- **WHEN** пользователь вызывает `GET /api/library/liked`
- **THEN** Hub возвращает треки, альбомы и артистов с ♥
- **AND** элементы отсортированы от новых к старым

#### Scenario: Отмена ♥
- **WHEN** пользователь снимает ♥ с трека
- **THEN** трек исчезает из `/api/library/liked`

#### Scenario: Импортированный ♥
- **WHEN** ♥ пришёл из импорта сервиса
- **THEN** он отображается в списке с `provenance: "import"`
- **AND** собственное решение пользователя имеет приоритет

#### Scenario: Пустой список
- **WHEN** у пользователя нет ♥
- **THEN** Hub возвращает пустые массивы
- **AND** не обращается к внешнему сервису
