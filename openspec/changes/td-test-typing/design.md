## Context

200 ошибок в 18 файлах. Основные источники:

| Файл | Ошибок | Типичный класс |
|---|---|---|
| `tests/test_tagger.py` | 49 | `reportOptionalMemberAccess`, `reportArgumentType` |
| `tests/test_wave.py` | 31 | `reportOptionalMemberAccess` |
| `tests/test_ai_links.py` | 29 | то же |
| `tests/test_imports.py` | 18 | то же |
| `tests/test_flow.py` | 11 | то же |

## Goals / Non-Goals

**Goals:**
- Ноль ошибок pyright в `hub/tests`.
- `tests` в гейте (`include`), без `exclude`-исключения.
- Снять файловые директивы-подавления.

**Non-Goals:**
- Не менять `app/` ради удобства тестов: если тест расходится с моделью, правится тест.
- Не вводить `Any`/`cast`/`getattr` как способ «заглушить» ошибку там, где можно сузить тип.
- Не менять набор проверок: количество и смысл assert'ов сохраняются.
- Не рефакторить сами тесты «заодно» (переименования, разбиение файлов) — только типы.

## Decisions

### 1. Правится тест, а не `app/`

Тест — потребитель контракта. Если pyright ругается на `user = (await s.execute(...)).scalar_one()` → `User | None`,
правильный фикс — `assert user is not None` (заодно проверка), а не `cast(User, ...)` и не расширение модели.
`cast(Any, ...)` допустим только для фейков, которые сознательно не наследуют продовый класс
(`svc.deezer = cast(Any, FakeDeezer())`, `FakeProvider`).

### 2. `skip_specs: true`, без capability `maintainability`

Правила проекта: `skip_specs: true`, если долг не меняет контракт (тулинг, формат, типы). Статическая проверка
тестов — внутренний тулинг, поведение системы не меняется. Спека `maintainability` не заводится.

### 3. Гейт включается последним шагом

Пока в `tests` есть ошибки, `include: ["app", "tests"]` сломал бы `uv run pyright` для всех. Поэтому:
сначала файлы по одному (каждый — зелёный локально), затем снятие директив, затем включение `tests` в гейт,
затем полный прогон.

### 4. Порядок — по убыванию числа ошибок

Сначала три крупнейших файла (89 ошибок из 200 — 45%), затем остальные. Так раньше видно повторяющийся паттерн,
и следующие файлы правятся быстрее.

## Risks / Trade-offs

- [Случайно ослабили проверку] → правило «ни один assert не удаляется»; diff ревьюится по каждому файлу; полный
  `pytest` должен остаться зелёным с тем же числом тестов.
- [Правка типа меняет поведение теста] → `assert x is not None` падает там, где раньше был `AttributeError`;
  это эквивалентно, но с внятным сообщением.
- [Директивы сняли, а ошибки остались] → снятие директив делается только после локального нуля в файле.
- [Гейт включили, но что-то пропустили] → финальный `uv run pyright` должен быть 0 на `include: ["app", "tests"]`.

## Migration Plan

1. Зафиксировать базовую линию: временный `pyright.tests.json`, посчитать ошибки по файлам.
2. Править файлы по одному (крупнейшие первыми), после каждого — pyright по файлу + `pytest` по файлу.
3. Снять файловые директивы в `test_mixes.py`, `test_insights.py`, добиться нуля.
4. Включить `tests` в `hub/pyrightconfig.json`, удалить временный конфиг.
5. Полный прогон: `pyright`, `ruff check`, `ruff format --check`, `pytest`.

Откат: правки только в тестах и конфиге; `git revert` коммита возвращает прежнее состояние (долг вернётся).
