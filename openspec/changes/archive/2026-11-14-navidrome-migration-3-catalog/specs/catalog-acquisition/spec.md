## MODIFIED Requirements

### Requirement: Жизненный цикл загрузки

Hub SHALL вести загрузку через статусы `queued`, `searching`, `downloading`, `tagging`, `importing`, `done`, `failed`, `needs_review`, `cancelled`. При отсутствии подходящего файла MUST возвращаться `needs_review` с кандидатами для выбора или ссылкой на страницу трека.

#### Scenario: Успешная загрузка
- **WHEN** найден и проверен подходящий файл
- **THEN** Hub скачивает его, тегирует и импортирует в библиотеку
- **AND** после фиксации блоба и записи каталога элемент становится `done` и получает `library_track_id` и `uid`

#### Scenario: Нужен выбор пользователя
- **WHEN** ни один кандидат не прошёл проверку или нет каталожной записи
- **THEN** элемент получает `needs_review`
- **AND** `GET /api/downloads/{id}` возвращает кандидатов

#### Scenario: Повтор с кандидатом или URL
- **WHEN** пользователь вызывает retry с `candidate_index` или `url`
- **THEN** Hub создаёт новую попытку загрузки с выбранным файлом

#### Scenario: Отмена до обработки
- **WHEN** пользователь отменяет загрузку, которую воркер ещё не начал
- **THEN** элемент получает `cancelled`
- **AND** задача не начинает обработку

#### Scenario: Отмена во время обработки
- **WHEN** пользователь отменяет загрузку, которую воркер уже выполняет
- **THEN** API выставляет `cancelled`, но воркер не проверяет статус в середине работы
- **AND** уже идущая загрузка MAY завершиться и перезаписать статус на `done`/`importing`
- **AND** временные файлы очищаются в `finally` задачи

#### Scenario: Очистка завершённых
- **WHEN** пользователь вызывает `POST /api/downloads/clear`
- **THEN** Hub удаляет `done` и `cancelled` элементы, кроме нужных как якоря порядка плейлиста
