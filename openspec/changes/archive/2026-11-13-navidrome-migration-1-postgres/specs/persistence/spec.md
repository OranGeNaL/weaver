## Purpose

Домен задаёт единый слой хранения Hub: СУБД Postgres, миграции Alembic, работу с JSONB, временные метки, резервное копирование и тестовую базу. Домен не владеет метаданными библиотеки и пользовательскими данными — он задаёт только правила их хранения.

## ADDED Requirements

### Requirement: Postgres как единственная СУБД

Hub SHALL использовать Postgres как единственную СУБД. Подключение MUST задаваться через `DATABASE_URL`; SQLite и файлы `*.sqlite3` MUST NOT поддерживаться. База MUST создаваться с UTF8 и non-C locale, пригодной для регистронезависимой работы с кириллицей.

#### Scenario: Запуск с Postgres
- **WHEN** Hub стартует с корректным `DATABASE_URL`
- **THEN** он подключается к Postgres и выполняет миграции до `head`

#### Scenario: SQLite в конфигурации
- **WHEN** `DATABASE_URL` указывает на SQLite или отсутствует
- **THEN** Hub завершает старт с понятной ошибкой и не создаёт файл БД

#### Scenario: Внешний Postgres
- **WHEN** `DATABASE_URL` указывает на внешний Postgres
- **THEN** Hub работает без локального контейнера Postgres

### Requirement: Миграции Alembic

Hub SHALL управлять схемой только через Alembic. Для чистой установки MUST существовать одна initial-миграция, создающая целевую схему Postgres; каждое последующее изменение схемы MUST сопровождаться новой миграцией.

#### Scenario: Чистая установка
- **WHEN** миграции применяются к пустой базе
- **THEN** создаётся полная целевая схема
- **AND** повторный `alembic upgrade head` не меняет схему

#### Scenario: Изменение схемы
- **WHEN** разработчик меняет модель
- **THEN** в change появляется миграция с осмысленным revision message
- **AND** проверены `upgrade head` и откат на предыдущую ревизию

### Requirement: JSONB и диалектная нейтральность

Колонки с JSON-данными SHALL использовать `JSONB`, включая типизацию SQLAlchemy. Запросы MUST использовать операторы Postgres и MUST NOT содержать SQLite-специфичный синтаксис (`json_extract`, `dialects.sqlite.insert`). По умолчанию используется `->>`; `->`/`?` — только там, где домен явно различает отсутствующий ключ и JSON-`null`. Числовые значения MUST приводиться к числовому типу явно.

#### Scenario: Запрос по JSON-полю
- **WHEN** домену нужно найти записи по значению внутри JSON
- **THEN** используется JSONB-оператор Postgres с явным кастом
- **AND** результат совпадает с прежней семантикой SQLite-запроса

#### Scenario: JSON-null и отсутствующий ключ
- **WHEN** ключ отсутствует или равен JSON-`null`
- **THEN** запрос различает эти случаи согласно сценарию домена
- **AND** это покрыто тестом

#### Scenario: Upsert
- **WHEN** домен вставляет запись с `ON CONFLICT DO NOTHING`
- **THEN** используется `dialects.postgresql.insert`
- **AND** повторная вставка не создаёт дубль

### Requirement: Регистронезависимый поиск

Hub SHALL обеспечивать регистронезависимый поиск по кириллице и латинице средствами Postgres, а не Python-fallback'ом, зависящим от поведения SQLite `LIKE`. `pg_trgm` MUST создаваться отдельной нефатальной миграцией и MAY отсутствовать; многотокенный поиск MUST сохранять семантику `artist + title + album` через SQL-запрос или объявленное изменение поведения.

#### Scenario: Поиск по кириллице
- **WHEN** пользователь ищет «кино» при наличии «Кино»
- **THEN** запись находится без дополнительной нормализации в Python

#### Scenario: Нет pg_trgm
- **WHEN** расширение `pg_trgm` недоступно
- **THEN** поиск работает через `lower`/`ILIKE`
- **AND** не падает

### Requirement: Временные метки

Hub SHALL хранить временные метки как `timestamptz` в UTC. `utcnow()` MUST возвращать timezone-aware `datetime.now(UTC)` и сохранять импортный шов; сравнения и bind-параметры MUST использовать aware-значения. API MUST отдавать даты в UTC с явным смещением или в документированном формате, совместимом с текущими клиентами.

#### Scenario: Запись события
- **WHEN** Hub сохраняет время события
- **THEN** в БД хранится timezone-aware значение UTC
- **AND** повторное чтение возвращает то же мгновение

#### Scenario: Сравнение сессии
- **WHEN** Hub сравнивает `expires_at` с текущим временем
- **THEN** обе величины timezone-aware
- **AND** сравнение не падает с `TypeError`

#### Scenario: Совместимость API
- **WHEN** клиент читает дату из API
- **THEN** формат остаётся совместимым с PWA
- **AND** сравнение дат не зависит от часового пояса процесса

### Requirement: Резервное копирование и восстановление

Hub SHALL ежедневно создавать логический бэкап Postgres через `pg_dump` и MUST хранить несколько последних копий. Бэкап MUST проверяться восстановлением в отдельную базу.

#### Scenario: Ежедневный бэкап
- **WHEN** наступает `library.backup_hour`
- **THEN** Hub создаёт дамп БД и сохраняет его в каталог бэкапов
- **AND** старые копии сверх лимита удаляются

#### Scenario: Проверка восстановления
- **WHEN** дамп создан
- **THEN** тест или проверка восстанавливает его в отдельную базу
- **AND** схема и контрольные строки совпадают

#### Scenario: Ошибка дампа
- **WHEN** `pg_dump` завершился ошибкой
- **THEN** Hub логирует ошибку и не удаляет предыдущие копии

### Requirement: Тестовая среда

Тесты Hub SHALL выполняться на Postgres. Шаблонная SQLite-БД MUST NOT использоваться как замена тестовой СУБД. `init_engine()` MUST читать только `TEST_DATABASE_URL` и падать, если она не задана; guard от совпадения с `DATABASE_URL` MUST жить в `app/db.py`. Каждый тест MUST получать чистое состояние; запрещено использовать рабочую БД.

#### Scenario: Запуск тестов
- **WHEN** выполняется `pytest`
- **THEN** тестовая БД создаётся в Postgres и мигрируется до `head`
- **AND** тесты не обращаются к рабочей БД

#### Scenario: Параллельные тесты
- **WHEN** тесты запускаются с `pytest-xdist`
- **THEN** каждый воркер использует изолированную базу или схему
- **AND** тесты не мешают друг другу

#### Scenario: Чистое состояние
- **WHEN** тест завершился
- **THEN** следующий тест не видит его данных
- **AND** `TEST_DATABASE_URL` не совпадает с `DATABASE_URL`
