## Purpose

Домен задаёт правила статической проверки типов Hub: воспроизводимый анализатор, отсутствие ошибок в рабочем
коде и порядок работы с неизбежными `cast`/`ignore`. Домен не описывает поведение продукта и не меняет
контракты API.

## ADDED Requirements

### Requirement: Статическая проверка типов Hub

Hub SHALL иметь воспроизводимую проверку статических типов для `hub/app`, закреплённую конфигурацией и версией
анализатора в репозитории. Проверка MUST выполняться без ошибок до завершения change'а; предупреждения MAY
оставаться.

#### Scenario: Запуск проверки
- **WHEN** разработчик запускает проверку типов по конфигурации репозитория
- **THEN** анализ покрывает `hub/app`
- **AND** результат не зависит от глобально установленной версии анализатора

#### Scenario: Ошибки типизации
- **WHEN** в `hub/app` остаются ошибки статической проверки
- **THEN** change не считается завершённым
- **AND** список ошибок ведётся в задачах change'а по группам

#### Scenario: Ложная ошибка анализатора
- **WHEN** тип гарантирован инвариантом, не выводимым анализатором
- **THEN** допускается `cast` или `# type: ignore[код]` с комментарием о причине
- **AND** поведение кода не меняется

#### Scenario: Поведение не меняется
- **WHEN** правки типизации применяются к модулю
- **THEN** публичные сигнатуры, схема БД, API и контракты клиентов остаются прежними
- **AND** тесты Hub проходят без изменений ожиданий
