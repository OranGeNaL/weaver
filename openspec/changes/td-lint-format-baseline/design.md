## Context

См. `proposal.md — Why`. `navidrome-migration-1-postgres` привёл `ruff check` к нулю, но
`ruff format --check` показывает 96 файлов: репозиторий никогда не прогонялся через `ruff format`
(`line-length = 120`, компактный ручной стиль). Поведение кода корректно, тесты зелёные (1081 passed).

## Goals / Non-Goals

**Goals:**
- `ruff check` и `ruff format --check` — без замечаний на всём `hub/`.
- Форматный коммит отделён от смысловых, чтобы diff читался.
- Версия `ruff` закреплена; порядок проверок зафиксирован в документации.

**Non-Goals:**
- Не менять `line-length`, набор правил и `per-file-ignores` ради «чистоты».
- Не переписывать логику, тесты и ожидания.
- Не форматировать `web/` (там Prettier/ESLint, отдельный тулинг) и `embedder/` (вне scope этого change'а).
- Не смешивать форматирование с другими изменениями.

## Decisions

### 1. Один форматный коммит

`ruff format hub/` отдельным коммитом с сообщением `style: ruff format` и записью в
`.git-blame-ignore-revs`. Альтернатива — форматировать «попутно» — отвергнута: смысловые diff'ы
становятся нечитаемыми, а review теряет фокус.

### 2. Версия и конфигурация

Версия `ruff` фиксируется в dev-зависимостях и `uv.lock`; `pyproject.toml` остаётся источником правил.
Никакие правила не отключаются: форматирование не должно требовать ослабления линтера.

### 3. Порядок проверок

`ruff check` → `ruff format --check` → `pytest` → (для web) `npm run typecheck`. Порядок фиксируется в
`hub/API.md` (раздел разработки) или `README.md`, чтобы проверка была воспроизводимой.

### 4. Безопасность изменений

`ruff format` меняет только представление кода. Контроль: `git diff -w` после форматирования не содержит
смысловых строк, полный `pytest` зелёный, `ruff check` остаётся нулевым.

## Risks / Trade-offs

- [Большой diff] → отдельный коммит + `.git-blame-ignore-revs`; ревью — по факту «только формат».
- [Конфликты с параллельной работой] → форматирование после мержа текущих change'ей, одной веткой.
- [Скрытое изменение поведения] → `pytest` и `git diff -w` как контроль.
- [Формат снова «уплывёт»] → проверка `ruff format --check` в наборе обязательных.

## Migration Plan

1. Закрепить `ruff` и `uv lock`.
2. `ruff format hub/` отдельным коммитом.
3. Прогнать `ruff check`, `ruff format --check`, `pytest`.
4. Добавить `.git-blame-ignore-revs` и раздел проверок в документацию.

Откат: `git revert` форматного коммита (он изолирован).
