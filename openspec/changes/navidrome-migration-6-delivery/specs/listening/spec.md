## MODIFIED Requirements

### Requirement: Подбор файла для прослушивания

Hub SHALL подбирать файл для `GET /api/listen?ref=...` тем же способом, что и загрузка: проверять библиотеку, каталог, порядок источников, длительность и версию. Результат MUST иметь вид `full`, `preview` или `library` и MUST кэшироваться. Библиотечный трек MUST адресоваться `ref=lib:<uid>`; `ref=nd:<id>` MAY поддерживаться как deprecated-алиас.

#### Scenario: Трек уже в библиотеке
- **WHEN** запрошен `ref=lib:<uid>`, который есть в библиотеке
- **THEN** Hub возвращает `kind: "library"`
- **AND** `uid` заполнен
- **AND** `nd_song_id` MAY быть заполнен как deprecated-алиас

#### Scenario: lib:<uid> в рекомендациях и событиях
- **WHEN** smart shuffle или событие прослушивания получает `lib:<uid>`/`uid`
- **THEN** Hub резолвит `lib:<uid>`/`uid` в `tracks.uid` и принимает наравне с `nd_song_id`

#### Scenario: q=mobile
- **WHEN** клиент в лимитной сети запрашивает библиотечный трек
- **THEN** PWA передаёт `q=mobile`
- **AND** Hub отвечает `X-HomeMusic-Variant`

#### Scenario: Старый lib:int
- **WHEN** запрошен legacy `ref=lib:<int>` до этапа 7
- **THEN** Hub находит тот же трек по внутреннему id
- **AND** возвращает `uid`
- **AND** на этапе 7 legacy-резолв удаляется

#### Scenario: Полный файл найден
- **WHEN** источник отдаёт подходящий полный файл
- **THEN** Hub возвращает `kind: "full"`, провайдера, битрейт и `stream_url`

#### Scenario: Полного файла нет
- **WHEN** ни один источник не дал полный файл
- **THEN** Hub возвращает `kind: "preview"` с 30-секундным превью Deezer

#### Scenario: Ничего не найдено
- **WHEN** нет ни полного файла, ни превью
- **THEN** Hub возвращает `404` или `502` в зависимости от причины

### Requirement: Потоковая отдача и Range

Hub SHALL отдавать аудио через `GET /api/listen/stream` с поддержкой `Range` и статусом `206`. Для источников без прямого HTTP-аудио Hub MUST сначала создать серверную копию и MUST продолжать её скачивание при обрыве соединения. Для библиотечного трека Hub MUST отдавать байты из локального hot-cache S3.

#### Scenario: Перемотка
- **WHEN** клиент отправляет `Range`
- **THEN** Hub возвращает запрошенный диапазон и `206`
- **AND** для недостижимого диапазона возвращает `416`

#### Scenario: Файл из библиотеки
- **WHEN** выбран `kind: "library"`
- **THEN** Hub отдаёт блоб через локальный hot-cache
- **AND** при промахе заполняет кэш из S3 и продолжает отдачу
- **AND** возвращает `Accept-Ranges` и `ETag` по `sha256`

#### Scenario: googlevideo
- **WHEN** выбран YouTube-файл
- **THEN** Hub скачивает серверную копию в локальный staging и отдаёт поток из неё
- **AND** при обрыве upstream возобновляет загрузку копии

#### Scenario: Источник без HTTP-аудио
- **WHEN** источник отдаёт HLS или не отдаёт прямой файл
- **THEN** Hub сначала скачивает копию и затем отдаёт её клиенту
